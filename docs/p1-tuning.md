# P1 정/오탐 튜닝

- 일자: 2026-10-27
- 환경: Mac mini M4 (arm64), OrbStack, WAF ModSecurity v3 + CRS 4.30.0 (DetectionOnly, PL1)
- 결과: 완료 — 정상 트래픽의 유일한 오탐(920350)을 근본 원인 제거로 해소, 탐지력은 유지

## 1. 목적

정상 사용 트래픽이 WAF 룰에 걸리는 오탐을 찾아 조치하고 근거를 문서화한다.
쿠팡 공고의 "WAF 정/오탐 분석·조치, 미탐 영역 개선"에 대응.

## 2. 오탐 수집 방법

- `scripts/normal_traffic.py`: 공격 페이로드 없는 정상 흐름 생성(회원가입·로그인·주문·로그아웃·파트너 API)
- 특수문자 포함 정상 입력을 의도적으로 섞음: 아포스트로피(O'Brien), 따옴표, `=`, `+`, `#`
- 전송 후 Wazuh에서 `panoptes_source=modsecurity` 매칭을 룰 ID·메시지별로 집계

## 3. 결과: 오탐 1종류뿐

| 룰 | 메시지 | 판정 |
|---|---|---|
| 920350 | Host header is a numeric IP address | 오탐(랩 환경 IP 접속) |

- 특수문자 정상 입력은 942(SQLi)·941(XSS)에 **걸리지 않음**
  - CRS 4.x의 libinjection이 정밀해 단순 특수문자로 오탐을 내지 않음을 실측 확인
- 즉 실질 오탐은 920350 하나

## 4. 920350 분석

- 발생 원인: Host 헤더가 도메인명이 아니라 숫자 IP(127.0.0.1:8080). CRS는 봇이 IP로 직접 접근하는 패턴으로 간주
- 오탐인 이유: 랩에서 IP로 직접 접속했기 때문. 실제 서비스는 도메인으로 접속
- WAF 설정 확인: `proxy_set_header Host $host` → nginx가 클라이언트 Host를 그대로 백엔드·룰 평가에 전달. 즉 클라이언트가 보내는 Host가 그대로 판정 대상

## 5. 조치: 근본 원인 제거(룰 비활성 아님)

- compose의 WAF에 `SERVER_NAME=shop.panoptes.lab` 추가
- 트래픽 스크립트가 `Host: shop.panoptes.lab`을 보내도록 수정
  - urllib은 Host 헤더를 URL 호스트로 덮어써 적용 안 됨 → http.client로 교체(Host를 지정한 대로 전송)

## 6. 검증 (양방향)

| 접속 방식 | 920350 | 의미 |
|---|---|---|
| Host=shop.panoptes.lab | 0건 | 정상 사용자 통과(오탐 해소) |
| Host=127.0.0.1:8080 | 발생(17건/14요청) | IP 직접 접근은 탐지 유지(미탐 없음) |

- WAF 컨테이너 자체 헬스체크: 25초 무요청 관찰 결과 920350 미발생 → 예외 룰 불필요

## 7. 판단 근거: 왜 룰을 끄지 않았나

- 920350 전체 비활성은 "IP로 직접 때리는 스캐너"에 대한 미탐 구멍을 만듦
- 오탐은 "룰을 끄는 것"이 아니라 "정상 트래픽을 정상답게(도메인 접속)" 만들어 해소하는 것이 우선
- 결과적으로 예외 룰 0개로 오탐 해소 + 탐지력 유지

## 8. 실무 참고: IP 형태 접근을 다루는 방식

920350을 무조건 끄지 않고 경로/목적별로 관리하는 패턴:

| 케이스 | 처리 |
|---|---|
| 헬스체크·LB 프로브 | 특정 경로(`/health`, `/healthz`)에 한해 예외 |
| 모니터링·업타임 체커 | 출발지 IP 화이트리스트 |
| 내부 서비스 간 통신 | 내부 대역 별도 정책, 또는 WAF를 외부 경계에만 배치 |
| IP 접근이 정상인 API | 룰을 detection-only/점수 완화(완전 비활성 아님) |
| 그 외 IP 직접 접근 | 스캐너 가능성, 탐지 유지 |

- 원칙: 룰 전체 비활성 지양 / 예외는 가장 좁게(경로·출발지IP·Host 조합) / 차단과 탐지 분리
- CRS는 tag 기반 exclusion(ctl:ruleRemoveById/ById), 경로 조건부 예외 제공
- Cloudflare WAF Exception, AWS WAF Scope-down statement도 같은 개념

## 9. 블로그 포인트

- "오탐 = 룰 끄기"가 아니라 "근본 원인 제거"가 먼저라는 판단 과정
- urllib이 Host 헤더를 못 바꾸는 함정(http.client로 해결) — 테스트 도구의 신뢰성
- 양방향 검증(정상 통과 + 공격 탐지)으로 미탐 없음을 입증
- CRS 4.x libinjection이 특수문자 정상 입력을 오탐하지 않는다는 실측
